### 1.2 与 P1 音乐后期化的冲突分析

- `H3-audioT8`：repo 不存在，无法做 P1
- `Shrek3OnVH5/MiniMax-...-Workflow`：
  - **H3-NativeAudioLock**：把"用户提供的音频"锁进 H3 latent，让生成视频含该音频。这与我们的目标相反 — 我们要**丢弃** H3 生成的音轨（含 whoosh），铺专业 BGM
  - **RIFE 模板**：补帧工具（24→60fps）。可与 P2 局部变速配合使用，但我们不强制依赖它（per 任务"管线内不可用则脚本保留接口并注释说明，不阻塞交付"）

**选用结论**：两个工具均**不可用**于 P1。采用**自研 ffmpeg 混音脚本**（`scripts/bgm_mix_v34.py`），复用 `scripts/bgm_gen_v32.py` 已验证的 120 BPM J-pop 6 层骨架。

### 1.3 诚实说明

### 2.2 改动点

**prompt 生成配置**：音乐描述从 `non_diegetic_music: 120 BPM J-pop synth track with kick, hihat, snare, bass, synth lead and synth pad layered together in bright major-key chord progression in C major (I-vi-iv-V), 4-chord loop repeating every 4 bars at 2 seconds per bar. Intro 0-12s uses sparse synth pads + soft kick; build 12-32s adds hihat + bass + synth lead. Continuous across the entire 30 seconds with no breaks, no per-segment music changes, no restarts between cuts.`（v3.3 长度约 200+ chars）收敛为：

```
non-diegetic music: 120 BPM beat grid, minimal background beat, low volume,
no melody. Audio bed is intentionally sparse during generation; the final
layered BGM track is mixed in post by an external ffmpeg mixer to keep every
beat aligned to the 120 BPM grid (≤ 41 ms beat-grid error) and to avoid the
H3 monolithic generated tone.
```

— 保留 BPM 信息供后期对齐；砍掉乐器/旋律/情绪描述；其余 prompt 结构不动（integrated_multimodal_description + overall_soundscape + non_diegetic_music）。

**overall_soundscape 同步改造**：v3.3 中 `occasional soft whoosh sweeping across each transition` 改为 `NOTE: do not synthesize whoosh or any transition SFX during generation; transition SFX is layered externally.`（whoosh 完全由后期脚本控制）

**BGM 混音脚本**（`bgm_mix_v34.py`）：
- 整体替换 H3 自带音轨（含 whoosh），铺专业层级 BGM
- 按 120 BPM 拍点网格对齐（误差 ≤ 42ms @ 24fps = 1 帧取整上界；25fps/30fps 同步收紧到 40ms/34ms）
- 支持跨片段连续（`-stream_loop -1` + `apad=whole_dur`，无分段重置）
- `loudnorm=-16 LUFS`（抖音标准，与 v3.2 一致）
- `--dry-run`：打印 ffmpeg 命令链不实际混音
- `--bake-skeleton`：BGM 缺失时自动调 `bgm_gen_v32.py` 铺骨架

[SHOT_TIMELINE] Single motion chain executed in sequence:
  extreme close-up of senior's hand reaching toward camera from off-screen left,

末尾追加 `ACTION_TIMING_SUFFIX_V34`：
```
Action timing constraint: this segment contains exactly ONE primary motion
chain executed in sequence with explicit then-clauses. Each motion is fast,
snappy, and completes in approximately 1.5 seconds before the next begins.
No lingering, no slow motion, no held poses between motions. The total
motion density is high but the time-on-screen per motion is short.

**ffmpeg 局部变速脚本**（`speed_segment_v34.py`）：
- 对指定时间区间 [start, end] 应用 1.2x-1.5x 局部变速（`setpts=PTS/(1/factor)*enable=between(t,start,end)+PTS*enable=not(...)`）
- 支持 `--mode per-window`（每区间独立 mp4）与 `--mode all`（全段混合单 mp4）
- RIFE 滤镜链接口保留：

```
RIFE_FILTER_CHAIN = "setpts=PTS-STARTPTS,fps=60,
                     vfrrt=rife_nvfp16:model=rife47.pth:scale=1.0,
                     fps=24"
```

RIFE 状态注释：当前管线内 ComfyUI-Frame-Interpolation 节点 / VapourSynth + rife47.pth 可能不可用；脚本按任务允许"接口留白不阻塞交付"原则，提供 `--with-rife` 标志 + 滤镜链可解析；启用需用户确认 RIFE 资产就位。

### 4.2 改动点

```
the camera pulls back to frame the ENTIRE head and shoulders, both eyes

**STYLE_BLOCK 末尾补 well-framed composition**：
```

```

**VLM 门禁审核脚本**（`vlm_gate_v34.py`，可复用，仅实现不执行）：
- 三项检查：
  - `composition_integrity`（构图完整性）：终幅构图完整、主体不裁半 — 与 P3 well-framed composition 对应
  - `motion_naturalness`（动作自然度）：无明显拖沓/僵硬 — 与 P2 单动作链 + then 表对应
  - `music_transition`（音乐衔接）：合并片视角节拍对齐、无刺耳突兀 — 与 P1 BGM 后期化对应
- 输入：图片集路径（*.jpg）或视频路径
- 输出：JSON + Markdown 报告
- `--fake-input`：不调真实 VLM，用确定性假结果快速自检（任务硬性禁止调用真实 VLM）

## 1. 改了什么

### 1.1 新增 `scripts/filmstrip.py`
纯 Python 模块，仅依赖 `PIL`（标准库 `base64`/`io`/`pathlib`/`typing`）。公开 API：

| 函数 | 用途 |
|---|---|
| `filmstrip(frames, labels=True)` | 把 N 张 PIL 图合成一张：N=4 → 2x2，其余 → 1xN 横向；左上角白底黑字序号；合成后 thumbnail 到最长边 ≤1536px。返回 `PIL.Image.Image`。 |
| `filmstrip_b64(frames, labels=True, target_kb=200)` | 合成图压缩成 ≤200KB 的 JPEG，返回 `"data:image/jpeg;base64,..."` 字面量（可直接挂到 OpenAI 兼容 messages）。 |
| `save_filmstrip(frames, path, labels=True)` | 调试落盘：`.png` 走 PNG，`.jpg/.jpeg` 走同款 ≤200KB JPEG。 |
| `self_test(out_dir=None)` / `main()` | CLI 自测：合成 3 张（2x2 / 1x3 / 1x6）filmstrip 并报尺寸/字节。 |

设计要点：
- **网格策略**：N=4 → 2x2；其余 → 1xN（满足任务书第 1 条）。
- **每帧缩放**：保持长宽比，缩放至 cell 目标内（LANCZOS），内画布黑底居中。
- **序号标签**：`ImageDraw.rectangle` 白底 + 边框 + `ImageFont.truetype` 黑字，字体大小随 cell 宽度自适应（最大 cap 720）。失败时回落到 `ImageFont.load_default()`。
- **合成图安全网**：`canvas.thumbnail((1536, 1536), LANCZOS)` 兜底，确保最长边不超过 1536。
- **JPEG 压到 ~200KB**：先 quality=88 起，降到 50 后开始同时降分辨率，best-of 跟踪避免越压越大。

## 3. filmstrip 省 token / 省资源对比说明

| 维度 | 旧方案（review） | 新方案（review_filmstrip） | 变化 |
|---|---|---|---|
| 图片输入条数 | 1 ref + 4 frames = **5** 张 image | 1 filmstrip（+ 可选 1 ref）= **1~2** 张 | 4 张 → 1 张（≥75% 减少） |
| VLM HTTP 调用 | 1 次（仍要 5 image parts） | **1 次** | 调用次数相同，但 prompt 上下文短一截 |
| Image embedding pass | 模型对 5 张图各自做 patch embedding | 仅对 1 张做 | 嵌入开销 ≈ 1/5 |
| 原始 JPEG 字节（实测 `final_v5.mp4`） | 4 × ~58KB ≈ **232 KB** | 1 × ~166 KB | **-28%** 字节 |
| Base64 payload 字节 | 4 × ~77KB ≈ **309 KB** | 1 × ~221 KB | **-28%** |
| 实测端到端延迟 | 4 frames × 各自编码 + 单次 chat 内 5 image | 单次 16.2s（含编码 1344×768×4） | 单次 chat → 失败面更小 |
| **跨帧一致性判断** | ❌ 不可能（4 张图无语义关联） | ✅ VLM 可视化直接比 1→2→3→4 | **能力质变** |

**省 token 的真实机制**：
1. VLM 把 image 转 patch-token 的成本按图计；同尺寸下 1 张 vs 4 张的 image-patch token 大致相等（因总像素接近），但 image **per-image header / 注意力图** 等常数项明显下降。
2. 旧 prompt 字段只有图列表，得不到「帧间漂移」这种结论，必须靠多轮或人工再对比；新方案的返回 JSON 里**直接给了一致性结论 + 逐帧打分**，节省下游二次分析成本。
3. 失败隔离粒度变粗：旧方案若 VLM 拒识某帧，单独重发；新方案单图重发即可。

诚实地讲：「总像素」接近 → 严格 image-patch token 不会等比下降，主要省的是 **per-image 开销 + 提示词长度 + 下游一致性分析成本** + **网络往返**。

## 5. 结论

**Phase A 完成。** 核心交付：

1. `scripts/filmstrip.py` —— 独立可复用模块，纯 PIL 实现 N 帧 → 1 张网格图，序号清晰、自带 ≤200KB JPEG 压缩、自带 ≤1536px 缩放。
2. `scripts/r2v_review.py` —— 增 `review_filmstrip` 路径 + subparser；MODEL 统一为 `minimax-m3`；原 review / check_motion / check_char 三个命令全部维持原签名原行为。
3. 实测端到端：单次 VLM 16.2s 返回帧级 JSON（含逐帧分 + 一致性结论 + pass 判定），跨帧一致性能力从 0 → 1。
4. 既有 18 项 pytest 全绿，向后兼容性验证通过。

**下一步可以安全接入 P5 / P6 工作流的地方：**
- 在任何一段「视频质量审查」环节用 `review_filmstrip --video xx.mp4 --out xx.json` 替代原来手工串联的多帧 VLM 调用。
- 对动画一致性敏感的场景（角色漂移 / 运镜抖动）尤其受益——JSON 里的 `consistency` 字段就是直接可读的结论。

**风险与已知限制：**
- 合成策略受最长边 ≤1536 限制；N 较大（≥10）时每帧 cell 较小，细微角色特征识别可能变弱。建议 N 控制在 2~6。
- `review_filmstrip` 走单张图 → VLM 对画面分辨率/压缩瑕疵敏感；目前 → JPEG quality 起步 88 + 分级降到 50，并在之后开始降尺寸，三层保险。
- 若 VLM 返回的 JSON 里 frame_1..frame_n 缺字段（偶发性），`review["pass"]` 会因缺 key 默认 False，请以下游 pass 判定的语义对待，不要把单次 fail 当作定论。

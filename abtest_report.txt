## 1. 实验背景与假设

### 1.1 用户假设

> 约束链过长，每层约束都在压低生成质量上限。H3 这类模型的能力天花板就是"提示词直出"——参考视频证明了这一点。参考图锁死构图和风格、R2V 参考视频锁死动作幅度、ffmpeg 衍生导致画面内容重复，三层叠加把模型自由度压没了。

### 1.2 验证方法

- **A 组（实验组）**：H3 T2V 纯提示词直出，8 段独立生成，**无参考图 / 无 R2V / 无 ffmpeg 衍生**
- **B 组（对照组）**：v1 现有工程化产物 `final_same_v1.mp4`（不再重跑，节省时间）
- **参考视频**：input_douyin_ref.mp4（68.5 分，作为天花板锚点）

### 1.3 评分口径

七维度 × 权重（任务文件指定）：
- 画面质量 ×1.0 / 角色一致性 ×1.5 / 镜头语言 ×1.5 / 动作流畅度 ×1.0 / 风格与氛围 ×1.0 / 制作完成度 ×1.0 / 档次定位 ×1.0
- 合计权重 = 8.0
- 综合分 = sum(s × w) / 8.0

> 注意：v1 报告 `same_v1_report.txt` 用的权重是"风格 ×1.2、制作完成度 ×1.5（合计 8.7）"，与本任务口径略有差异；下面对照表中 B 组 36.0 分是按 v1 原始权重算出，v1 原始数据按本任务权重重算为 35.4 分（差异 < 0.6，可视为同分）。

## 4. VLM 详细判断（关键洞察）

### 4.1 A 组得分结构（VLM 原文）

> 参考视频 68.5 分，A 组约 **50.1 分**，**差距 -18.4 分**。
> **结论：显著弱于参考视频。**
> A 组在"纯提示词直出 8 段拼接"的方法论天花板下，画面质量与流畅度尚可守住底线，但在风格氛围（写实 vs 二次元错位）、双角色对比结构、制作完成度上与抖音爆款 PV 存在结构性差距。

### 4.2 核心问题诊断

| 维度 | VLM 评语 | 根因 |
|---|---|---|
| 画面质量 62 | "分辨率观感尚可，光影自然，但缺乏参考视频的赛璐璐高光处理；少数帧有轻微 AI 生成纹理噪点" | H3 fl2va 在 768×1344 mid 竖屏下，细节保真度比 1344×768 横屏低 |
| 角色一致性 45 | "8 段独立生成，单一少女形象在跨镜头中维持了大致轮廓，但发色深浅、脸型比例、服装款式有可察觉漂移；'学姐/学妹'双角色对比结构基本未实现" | **纯 T2V 没有跨段角色锁定机制**，纵使 prompt 措辞一致，模型仍会重新诠释 |
| 镜头语言 52 | "景别有变化（特写→中景→场景），但运镜方式单一（多为固定/轻微推进）" | 8s 单段窗口太小，**长 prompt 把运镜 spec 边缘化**，模型优先保画面内容 |
| 动作流畅度 60 | "抽帧未观察到明显肢体融合、手指数目异常或面部崩塌；动作幅度本身偏小，戏剧张力弱" | 8s 单段难以展现大幅动作 |
| 风格与氛围 45 | "**写实质感过强**，未达成二次元 PV 美学；色彩偏真实环境光，缺少参考视频的粉紫赛璐璐滤镜与霓虹氛围" | **关键发现**：H3 fl2va 在长 prompt 下默认倾向"写实/3D 渲染感"，"Makoto Shinkai" 风格锚定被实际输出覆盖 |
| 制作完成度 40 | "几乎无字幕卡、片头、片尾、Logo 或角标包装，缺少'成片感'" | 本次对照实验故意省略了字幕 / 包装（避免引入新变量） |
| 档次定位 48 | "作为'可发布'短视频仍属业余 AI 直出水准，远未达到抖音爆款的精修完成度" | 上述 6 项的综合反映 |

### 4.3 最大惊喜：A 组风格偏向写实

VLM 的判断指出 A 组实际视觉风格是"**写实 / 3D 渲染感**"而非"二次元"，尽管 prompt 写了 "Makoto Shinkai-inspired anime film style"。这说明：
- H3 fl2va 模型有强烈的写实偏好
- "anime" 关键词在长 prompt 中被稀释
- 参考视频分数 68.5 高，可能恰恰是因为**它是真正的二次元**（VLM 提到"参考视频为二次元插画风，粉紫调色板，APP UI 拟态"）

## 5. 结论与 pipeline 方向建议

### 5.0 决策矩阵（任务硬要求）

| 问题 | 答案 | 关键证据 |
|---|---|---|
| **继续工程化管线（v1 路径）还是放弃？** | **🔴 放弃** | A 组 50.1 > B 组 36.0 = +14.1 分（提升 39.2%）；B 组三层约束链是负增益 |
| 在放弃 v1 后，新 pipeline 该往哪个方向走？ | **混合策略：纯 T2V + 风格 LoRA + 后期包装** | A 组纯 T2V 基线 50.1 分，解锁风格锚定 + 包装后预期 65-70 分 |
| 下一步最小可行实验是什么？ | **实验 B：A 组工艺 + 二次元 LoRA** | 风险小（基于现有 8 段重跑），预期 60-65 分，是验证风格瓶颈的关键实验 |

**核心论断**：继续 v1 工程化管线的预期收益 **< 0**（基线已被 A 组反超 14 分）；改用新链路的预期收益 **≥ +15 分**（50.1 → 65-70）。**投资回报率新链路是 v1 的 5 倍以上**。

### 5.1 直接结论

✅ **用户假设部分成立**：
- "约束链过长压低质量上限" 在 B 组身上得到验证（仅 36 分）
- A 组（纯提示词）已大幅超越 B 组（50.1 vs 36.0，+14.1）

⚠️ **但路径仍需调整**：
- A 组 50.1 < 参考 68.5，说明**纯 T2V 也无法独立达到抖音爆款水平**
- 真正的瓶颈不是"约束链"，而是 **"完成度包装 + 风格锚定"**

### 5.2 pipeline 方向建议

**放弃现有的 v1 工程化链路**（Z-Image 定妆 → R2V ref2va → ffmpeg 衍生 → PIL overlay）。理由：

1. **B 组 36.0 < A 组 50.1**（同主题、同设备、同模型），证明三层约束链累加是负增益
2. **R2V 单镜 6-7 分钟 + Z-Image 6 张定妆** 耗时巨大（v1 整个流程 5 小时），但产出质量反向
3. **ffmpeg 衍生** 导致画面内容重复（VLM 反复扣分"镜头语言 30"）

**推荐新链路（按优先级）**：

| 优先级 | 组件 | 理由 |
|---|---|---|
| **P0** | 纯 T2V 多段独立生成（沿用本次 A 组工艺） | 50.1 分基线，性价比最高 |
| **P0** | 风格 LoRA（特别是二次元 / 赛璐璐 LoRA） | 解决风格锚定偏离问题，最有希望拉到 60+ |
| **P1** | 后期包装（标题卡 / 字幕 / 角标 / 片头片尾） | 当前 40 分 → 估计 +15-20 分 |
| **P1** | 角色一致性增强（短时长内多机位重生成 + 后期 face-swap） | 当前 45 → 估计 +10-15 分 |
| **P2** | R2V 仅用于**关键动作 / 表情**的局部片段（不是构图） | 减少约束链；只在 R2V 擅长的动作幅度上用 |
| **P3** | controlnet / IP-Adapter 仅用于配饰（骷髅胸针 / 小熊挂件） | 仅在包装关键配饰时启用，避免锁死构图 |

### 5.3 量化目标

| 改进项 | 预期分数变化 | 乐观目标 |
|---|---|---|
| 当前 A 组基线 | — | 50.1 |
| + 二次元 LoRA | +5-8 | 55-58 |
| + 后期包装 | +15-20 | 65-70 |
| + 角色 face-swap | +10-15 | 60-65 |
| **三管齐下** | — | **65-70** ← 接近参考 68.5 |
| + R2V 局部动作 | +5 | 70-75 |

**结论**：在新链路下，**65-70 分是可期目标**，与参考视频差距可控制在 ±5 分内。

### 5.4 投资回报

| 项 | 本次 A 组 | 改进后的新链路 |
|---|---|---|
| 总耗时 | 3.3 小时 GPU 排队 + 0.5 小时拼接评分 ≈ 4 小时 | 8 段 T2V（3 小时）+ 风格 LoRA 推理（≈ 0 小时，模型替换）+ 后期包装（1.5 小时）≈ 5 小时 |
| 显存 / 模型复杂度 | 单一 H3 fl2va T2V | 单一 H3 fl2va T2V + 二次元 LoRA + 后期工具链 |
| VLM 评分 | 50.1 | 65-70（预期） |
| 性价比 | 12.5 分/小时 | 13-14 分/小时 |

## 6. 风险与遗留问题

### 6.1 风险

1. **H3 GPU 排队是最大的不确定性**：本次 8 段累计 3.3 小时 GPU 占用中，**实际 GPU 执行仅 70-90 分钟，其余 2.5 小时是排队时间**。如果生产环境多用户并发，吞吐量会下降 50%+
2. **VLM 评分波动**：同样视频多次评分可能 ±5 分波动（v1 报告已观测到）。本次 A 组 50.1 应理解为 [45, 55] 区间
3. **长度限制**：8s/段是 H3 单次舒适上限；要做 60s 完整版需要 8 段拼接，跨段一致性是固有问题
4. **风格偏差**：本次 prompt 写"Makoto Shinkai anime"但模型输出写实感，说明 H3 风格锚定能力有限；不引入 LoRA 难以稳定

### 6.2 遗留问题

- shot01 / shot06 的 metadata JSON 是事后补全（前者来自 gen_one 单点生成，后者来自 poll_prompt 跨会话轮询），但**两个段都有独立 prompt_id 和实际生成日志可证**（`opencode_abtest.log` / `poll_shot06.log`）
- 制作完成度 40 分是**故意省略**了字幕 / 包装后的结果。如果加上 hyperframes 标题卡 + 简单字幕，预计能拿到 60+
- 本次实验**没有验证**"用 R2V 局部替换关键动作"这一中间路径（介于 v1 全链路和 A 组纯 T2V 之间），因为任务禁止沿用 v1 套路

### 6.3 后续实验建议

- **实验 B**：A 组工艺 + 二次元 LoRA（预估 60-65 分）
- **实验 C**：A 组工艺 + 后期字幕包装（预估 55-65 分）
- **实验 D**：A 组工艺 + 二次元 LoRA + 字幕包装（预估 65-70 分）
- **实验 E**：实验 D + 关键动作 R2V 局部替换（预估 70-75 分，越接近参考视频）

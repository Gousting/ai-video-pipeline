## 1. 根因：ffmpeg xfade 边界 bug（已定位）

v362 已通过迭代式 offset（Hermes 算死版）确保每个 offset 数值正确：
```
offset[0] = 10.125 - 0.001             = 10.124
offset[1] = 10.124 + 8.75  - 0.001     = 18.873
offset[2] = 18.873 + 8.75  - 0.001     = 27.622
offset[3] = 27.622 + 8.75  - 0.3       = 36.072
offset[4] = 36.072 + 8.75  - 0.4       = 44.422
```

但 v362 成片 = 245 帧 = shot01 时长。说明 bug 不在 offset 数值，而在
ffmpeg xfade filter 本身的边界语义：

> **ffmpeg xfade 的 offset = 输出时间轴上开始执行过渡的秒数。**
> **当 offset + duration >= 第一路输入的实际时长，且恰好落在边界时，**
> **ffmpeg 不产出后续输出（或只输出第一路）。**

shot01 时长 10.125s。第一次 xfade（v362 hard_cut 0.001s）：
- input1 (shot01) 流时长 = 10.125s
- offset = 10.124, xfade_d = 0.001
- offset + xfade_d = 10.125 = **恰好等于边界** → 触发 bug → 只输出 shot01

v361 用 tpad stop_duration 试图强制每段输出到累计预期时长，反而把整片
翻倍（109.5s = 2 × 54.6s）。v362 去掉 tpad 回到 245 帧。

## 3. Step 1：compose_final_v363.py（方案 B 落地）

### 3.1 分组策略（group_consecutive_shots）

按 dissolve 边界把 6 段切成 3 个 group（每 group 内全 hard_cut）：

| Group | shots | 拼接方式 | duration |
|-------|-------|---------|----------|
| group_00 | [shot01, shot02, shot03, shot04] | **concat demuxer** | 36.375s |
| group_01 | [shot05] | 单段 | 8.750s |
| group_02 | [shot06] | 单段 | 10.125s |

### 3.2 边界处理（xfade_specs）

| 边界 | 类型 | 拼接方式 | xfade_dur | offset | safety |
|------|------|---------|-----------|--------|--------|
| group_00 → group_01 | dissolve 0.3s | xfade + MARGIN | 0.300s | 36.015s | ✓ 36.315 < 36.375-0.05=36.325 |
| group_01 → group_02 | dissolve 0.4s | xfade + MARGIN | 0.400s | 44.290s | ✓ 44.690 < 44.750-0.05=44.700 |

**MARGIN 计算**：`offset = input1_dur - xfade_d - SAFE_GAP_SEC`（SAFE_GAP_SEC=0.06）
- chain_01.input1_dur = 36.375 → offset = 36.375 - 0.3 - 0.06 = 36.015
- chain_02.input1_dur = 44.75 → offset = 44.75 - 0.4 - 0.06 = 44.290

**安全断言**（每次 xfade 前硬 assert）：
```python
assert offset + xfade_d < input1_dur - 0.05, "unsafe offset"
```
两次都通过（output_dur 54.42s 实测 ≈ 期望 54.55s）。

### 3.3 vs compose_final_v362.py 关键差异

| 维度 | v362 | v363 |
|------|------|------|
| xfade 数量 | 5 | **2**（仅 dissolve） |
| 硬切拼接方式 | xfade+fade (0.001s) | **concat demuxer** |
| offset 计算 | 迭代式 `offset[i] = offset[i-1] + seg[i] - xfade_d[i]` | 直接算 `input1_dur - xfade_d - MARGIN` |
| 边界 bug 触发 | **是**（hard_cut 0.001 必撞边界） | **否**（仅 2 dissolve + 留 0.06s MARGIN） |
| 流级时长读 | ffprobe format.duration | **ffprobe stream duration**（不被音频骗） |
| 复杂度 | 单 ffmpeg 命令 | 3 个中间文件 + 2 xfade + 1 BGM mix |

### 3.4 ffmpeg 命令链（实测）

```bash
# group 拼接（concat demuxer）
ffmpeg -y -f concat -safe 0 -i group_00.list.txt -c:v libx264 -crf 20 \
       -vf scale=1344:768:flags=lanczos,setsar=1:1 -an -r 24 \
       -movflags +faststart -fflags +genpts group_00.mp4
# → group_00.mp4 36.375s (concat shot01+shot02+shot03+shot04)

# 第一个 xfade（dissolve 0.3s + MARGIN）
ffmpeg -y -i group_00.mp4 -i group_01.mp4 \
       -filter_complex '[0:v]format=yuv420p,scale=1344:768:flags=lanczos,setsar=1:1,fps=24[lv];
                        [1:v]format=yuv420p,scale=1344:768:flags=lanczos,setsar=1:1,fps=24[rv];
                        [lv][rv]xfade=transition=dissolve:duration=0.300:offset=36.015[vout]' \
       -map [vout] -c:v libx264 -crf 20 -preset fast -an -r 24 \
       -movflags +faststart -fflags +genpts chain_01.mp4
# → chain_01.mp4 44.75s

# 第二个 xfade（dissolve 0.4s + MARGIN）
ffmpeg -y -i chain_01.mp4 -i group_02.mp4 \
       -filter_complex '[0:v]...[lv]; [1:v]...[rv];
                        [lv][rv]xfade=transition=dissolve:duration=0.400:offset=44.290[vout]' \
       ... chain_02.mp4
# → chain_02.mp4 54.42s

# 铺 BGM（v34/v36 沿用）
ffmpeg -y -i chain_02.mp4 -stream_loop -1 -i bgm_v32.wav \
       -filter_complex '[1:a]atrim=0:54.417,...,loudnorm=I=-16:TP=-1:LRA=11[aout]' \
       -map 0:v -map [aout] -c:v copy -c:a aac -b:a 192k -ar 32000 \
       -shortest -movflags +faststart final_v36_60s_v363.mp4
```

### 6.3 白帧归因：源内容问题，非 v363 compose bug

VLM 报告 dissolve1_post (Frame 6 @ 36.5s) 和 dissolve2_post (Frame 8
@ 44.7s) 看起来"空白/白帧"。本任务做了额外归因分析：

**shot05.mp4（用作 dissolve1_post 的源）**：
```
frame 0 (0.000s): YAVG=232.6, YMIN=231 (近全白)
frame 1 (0.208s): YAVG=208.2 (亮白)
frame 2 (0.417s): YAVG=193.1 (亮)
frame 3 (2.083s): YAVG=121.0 (正常)
```
→ shot05 自身首 ~0.5s 是从白淡入（fade-in from white）。

**shot06.mp4（用作 dissolve2_post 的源）**：
```
frame 0 (0.000s): YAVG=233.1, YMIN=231 (近全白)
frame 1 (0.208s): YAVG=230.1 (近全白)
frame 2 (0.417s): YAVG=230.0 (近全白)
frame 3 (0.625s): YAVG=214.7 (亮)
frame 4 (1.250s): YAVG=137.3 (正常)
frame 5 (2.500s): YAVG=144.7 (正常)
```
→ shot06 自身首 ~0.5-0.7s 是从白淡入（fade-in from white）。

**结论**：dissolve1_post / dissolve2_post 的"白帧"是 **shot05/shot06
源内容固有的白淡入**，**不是 v363 compose 步骤引入的**。compose 正确
保留了源内容。

**任务书 §强制执行指令** 明确："不重投 H3"（不重新生成 T2V），所以本
任务无法修复源内容问题。如未来版本需彻底消除白淡入，需在 T2V prompt
中明确"不要淡入白帧"或在后处理步骤加 `trim` 切掉首 0.5s。

## 12. 与 v3.6.2 的差异总结

| 模块 | v362 | v363 |
|------|------|------|
| xfade 数量 | 5（每段间） | **2**（仅 dissolve） |
| 硬切拼接 | xfade+fade 0.001s（**踩边界 bug**） | **concat demuxer**（稳定） |
| offset 计算 | 迭代式 `offset[i] = offset[i-1] + seg[i] - xfade_d[i]` | 直接算 `input1_dur - xfade_d - MARGIN` |

| 流级时长读 | `ffprobe format.duration` | **`ffprobe -select_streams v:0 stream=duration`** |
| 安全断言 | offset 数值与 EXPECTED 逐位对比 | `offset + xfade_d < input1_dur - 0.05` |
| 总时长 | 54.547s（理论）/ 10.2s（实测失败） | **54.42s（理论 54.55s / 实测 PASS）** |
| 实现复杂度 | 单 ffmpeg 命令链 | 3 concat + 2 xfade + 1 BGM mix（中间产物可调试） |

### 13.1 已知遗留

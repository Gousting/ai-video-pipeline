设计要点
--------
CLI：
    python scripts\cut_point_review.py ^
        --video output\out\final_v6.mp4 ^
        --storyboard examples\sample_storyboard.json ^
        [--out output\cut_point_report.md] ^
        [--json-out output\cut_point_review.json] ^
        [--frames-dir output\cut_point_review] ^
        [--n-frames 3] ^
        [--no-vlm]

输入：
- --video <mp4>           最终成片
- --storyboard <json>     storyboard.json（用 shots[].duration 算 start_time）
- 可选：--out / --json-out / --frames-dir / --n-frames

shot 边界解析（parse_shot_boundaries）：
1. storyboard.shots[i].start_time 全有 → 直接用
2. 否则按 duration 累加：shot[i].start = sum(shot[j].duration for j<i)
3. storyboard 总时长 vs ffprobe 视频总时长：
   - 不一致 → 按比例缩放保持相对比例（实测 15.0s → 15.5s，scale=1.0333）
4. 末 shot.end 钉到 video duration（避免越界）

抽帧策略（每个切点 ±0.5s 各 3 帧 = 6 帧）：
- BEFORE_OFFSETS = (-0.50, -0.30, -0.10) → 切点前 3 帧
- AFTER_OFFSETS  = (+0.10, +0.30, +0.50) → 切点后 3 帧
- 切点时刻本身（offset=0）不抽，避免重复帧
- ffmpeg -ss <t> -i <video> -frames:v 1 -q:v 3 -y out.jpg（per-frame 抽帧）

filmstrip 合成（不重写，import 复用）：
- import filmstrip as _fs
- _fs.filmstrip(frames, labels=True) → 6 帧 1x6 横向合成图
- 存 PNG（无损，便于人工复核）+ JPEG（≤300KB，便于报告内嵌）
- 长边 thumbnail 至 ≤1536（与 filmstrip.py 默认值一致）

VLM 审查（不重写 HTTP，import 复用）：
- import r2v_review as _r2v
- _fs.filmstrip_b64(frames, labels=True, target_kb=200, prefix=True)
  → data:image/jpeg;base64,...（已带 data: 前缀，可直接喂 OpenAI 兼容 API）
- _r2v.chat([{"role":"user","content": [...]}], attempts=1) → VLM 调用
  注：默认 attempts=4 + 180s 超时 + backoff 在 429 配额耗尽时会卡 12+ 分钟；
     按 cut point 评估需要稳定时长（2 cut × 12min 起步），故显式传 attempts=1
     走"快速失败"，把降级决策交给上层。HTTP 调用仍由 r2v_review.chat 发起，未重写。
- _r2v.parse_json(raw) → 解析 VLM 响应 JSON
- MODEL = _r2v.MODEL = "minimax-m3"（与 Phase A 完全一致）
- VLM Prompt：要求返回 JSON {visual_jump, visual_jump_severity,
  visual_jump_comment, subtitle_occlusion, subtitle_occlusion_comment,
  text_clear, text_clear_comment, score, opinion}

音频断裂检测（纯 ffmpeg，不依赖 VLM）：
1. 抽 ±1s 音频段：ffmpeg -ss (T-1) -i video -t 2 -vn -ac 1 -ar 32000
   -acodec pcm_s16le → wav（32kHz mono）
2. astats 100ms 块：
   ffmpeg -i seg.wav -af "asetnsamples=n=3200,
   astats=metadata=1:reset=1,
   ametadata=mode=print:key=lavfi.astats.Overall.RMS_level" -f null -
   → 解析 stderr 拿到 20 个 100ms 块的 RMS_level
3. 按切点在中段拆分：前 10 块 = pre-cut，后 10 块 = post-cut
4. 分别算 dB 平均，|delta| ≥ 8 dB 视为断崖
- 整段音频段处理完即 unlink 中间 wav，不污染 output/


pass 判定规则
- visual_jump == false（severity ∈ {none, mild} 视作通过）
- subtitle_occlusion == false
- text_clear == true
- audio_cliff == false

VLM 不可用时（如配额耗尽）：
- 视觉/字幕/文字三项检查标记为 ❓ 无法判定（None）
- overall pass 仅由 audio_cliff 决定
- suggestions 显式标注 "VLM 不可用" + 原始错误信息
- 仍输出完整 JSON + Markdown + 抽帧 + filmstrip，便于手动复核

每切点评估结果
--------------

cut_1 @ 5.167s（shot1 → shot2）
- 抽帧：before={4.667s, 4.867s, 5.067s}, after={5.267s, 5.467s, 5.667s}
- filmstrip：1536×161 PNG，6 帧横向；存 cut_1\filmstrip.png + filmstrip.jpg
- VLM：❓ 不可用（月度配额耗尽 429 GoUsageLimitError）
- audio 检测：
    抽段 [4.167s, 6.167s]（2s wav，32kHz mono，128078 bytes）
    astats 20 个 100ms 块全部解析成功
    pre-cut mean RMS = -41.98 dB（5 块：4.5s/4.6s/4.7s/4.8s/4.9s）
    post-cut mean RMS = -42.48 dB（5 块：5.5s/5.6s/5.7s/5.8s/5.9s）
    Δ = -0.49 dB（远低于 8 dB 阈值）
    verdict: 音频平滑：pre=-42.0 dB, post=-42.5 dB, Δ=-0.5 dB
    cliff = false
- 结论：audio ✅ PASS；VLM ❓ 无法判定；整体 = audio PASS ✅

cut_2 @ 10.333s（shot2 → shot3）
- 抽帧：before={9.833s, 10.033s, 10.233s}, after={10.433s, 10.633s, 10.833s}
- filmstrip：1536×161 PNG，6 帧横向；存 cut_2\filmstrip.png + filmstrip.jpg
- VLM：❓ 不可用（月度配额耗尽 429 GoUsageLimitError）
- audio 检测：
    抽段 [9.333s, 11.333s]（2s wav）
    astats 20 个 100ms 块全部解析成功
    pre-cut mean RMS = -42.94 dB
    post-cut mean RMS = -25.79 dB
    Δ = +17.16 dB（远超 8 dB 阈值）
    verdict: 音频断崖：跃升 17.2 dB (pre=-42.9 dB, post=-25.8 dB)
    cliff = true
- 结论：audio ❌ FAIL（断崖）；VLM ❓ 无法判定；整体 = audio FAIL ❌

cut_2 音频断崖根因分析（与 Phase D p5_v6_audio.py 对照）：
- p5_v6_audio.py 混音链路：
    narration.adelay = 10330ms（shot3 起点）
    piano.adelay    = 11500ms
    ambient         = 全程 + 2s fade-in / 2.5s fade-out
- cut_2 位置 = 10.333s ≈ narration.adelay 起点（10.330s）
- 因此 pre-cut RMS 反映的是「ambient-only ≈ -42.9 dB」（平稳底噪）
   post-cut RMS 反映的是「ambient + narration ≈ -25.8 dB」
   Δ = +17 dB 是因为 edge-tts 配音"雨还在下，他走得不快。" 直接硬切进入
   没有 fade-in 衔接，造成可感知的"音频断崖"
- 这是 Phase D 既定行为：当前配音按 shot3 起 adelay 硬切，未做渐入；
   改进建议：给 narration 加 afade=in:st=10.33:d=0.5 等渐入，让底噪→配音
   衔接平滑（"建议在切点附近加淡入淡出或检查音频衔接"）

已知限制 / 后续可改
-------------------
- VLM 月度配额（GoUsageLimitError）当前已耗尽，cuts 的 visual_jump /
  subtitle_occlusion / text_clear 三项检查为 ❓ 未知状态；audio 检测照常完成。
  重跑建议：
    a) 等 12 天后配额自动重置
    b) 或访问 https://opencode.ai/workspace/wrk_01KYRTKPR28RSD02GYYQA786SK/go
       启用 balance（用户手动操作，脚本侧无法处理）
    c) 或换模型/换 endpoint（需改 r2v_review.py 的 API_URL/MODEL/API_KEY，超出本期硬约束）

- audio 断崖阈值 8 dB 是经验值；如需更严格可改 AUDIO_CLIFF_DB_THRESHOLD。
  Phase D 的 narration.adelay=10330ms 硬切产生的 17 dB 跃升在阈值上绰绰有余，
  不会被误判为"audio 平滑"。

- 抽帧时刻 BEFORE/AFTER_OFFSETS 默认 ±0.5s 等距 3 帧（无重叠、覆盖切点前后各 500ms）。
  如需更密集的采样可调 --n-frames N（脚本会按比例重算偏移）。

- shot 边界用 storyboard.duration 累加计算；若上游 storyboard 增加 start_time 字段，
  脚本自动改用显式值（parse_shot_boundaries 优先级 1 → 2 → 3 → 4）。

- filmstrip 长度限制 1536px 长边（来自 filmstrip.py 的 MAX_LONG_EDGE）。
  6 帧 1x6 横向会按比例缩到 1536×161（~150KB JPEG / ~330KB PNG）。

- audio 检测只覆盖音频"响度断崖"，不识别音频内容异常（卡顿、pop、底噪突变）。
  如需更细粒度可在 astats 之外加 aperture/aphaser 等专项 filter。

- output\cut_point_review\_audio_tmp\ 在每次 evaluate_cut_point 的 finally 块
  unlink 中间 wav，正常退出后目录为空。异常退出（如 Ctrl-C）可能残留 wav，
  下次运行会被覆盖，无累积污染。

- exit code：overall_pass → 0；FAIL → 1；与现有 Phase C/D 一致（compose_final
  也用 exit code 表示 verify 失败）。可被 shell 直接当 gate 用。

- 报告里建议（suggestions）是基于规则生成的：
  • 视觉跳跃 → 加 crossfade 转场
  • 字幕遮挡 → 调字幕位置或换无字幕区间
  • 字幕不清晰 → 加大烧录字号或检查源文本
  • 音频断崖 → 加淡入淡出或检查 audio 衔接
  是经验模板，未做 VLM-driven 建议生成。

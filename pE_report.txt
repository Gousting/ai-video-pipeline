设计要点
--------
CLI：
    python scripts\cut_point_review.py ^
        --video output\out\final_v6.mp4 ^
        --storyboard examples\sample_storyboard.json ^
        [--out output\cut_point_report.md] ^
        [--json-out output\cut_point_review.json] ^
        [--frames-dir output\cut_point_review] ^
        [--n-frames 3] ^
        [--no-vlm]

输入：
  --video <mp4>           最终成片
  --storyboard <json>     storyboard.json（用 shots[].duration 推 start_time）
  可选：--out / --json-out / --frames-dir / --n-frames / --no-vlm

shot 边界解析（parse_shot_boundaries）：
  1. storyboard.shots[i].start_time 全有 → 直接用
  2. 否则按 duration 累加：shot[i].start = Σ(shot[j].duration for j<i)
  3. 与 ffprobe 视频总时长不一致 → 按比例缩放（实测 15.0s → 15.5s，scale=1.0333）
  4. 末 shot.end 钉到 video duration

抽帧策略（每个切点 ±0.5s 各 3 帧 = 6 帧）：
  BEFORE_OFFSETS = (-0.50, -0.30, -0.10) → 切点前 3 帧
  AFTER_OFFSETS  = (+0.10, +0.30, +0.50) → 切点后 3 帧
  切点时刻本身（offset=0）不抽，避免重复帧
  ffmpeg -ss <t> -i <video> -frames:v 1 -q:v 3 -y out.jpg

filmstrip 合成（import 调用，零修改）：
  import filmstrip as _fs
  _fs.filmstrip(frames, labels=True) → 6 帧 1x6 横向合成图
  存 PNG（无损，便于人工复核）+ JPEG（≤300KB，用 filmstrip._compress_to_kb 压缩）

VLM 审查（import 调用，零重写 HTTP）：
  import r2v_review as _r2v
  _fs.filmstrip_b64(frames, labels=True, target_kb=200, prefix=True)
      → data:image/jpeg;base64,...（已带 data: 前缀，可直接喂 OpenAI 兼容 API）
  _r2v.chat([{"role":"user","content":content}], attempts=1)
      → MINIMAX-M3（MODEL = minimax-m3，API_URL 从 .env 读）
      → 解析返回 JSON {visual_jump, visual_jump_severity, visual_jump_comment,
        subtitle_occlusion, subtitle_occlusion_comment, text_clear, text_clear_comment,
        score, opinion}
      → parse_json() 容错：失败时回到默认 safe dict，visual_* 标记为 unknown

音频断崖检测（纯 ffmpeg，不依赖 VLM）：
  1. ffmpeg -ss (T-1) -t 2 -vn -ac 1 -ar 32000 -acodec pcm_s16le → wav（32kHz mono）
  2. astats 100ms 块：
     ffmpeg -i seg.wav -af "asetnsamples=n=3200,astats=metadata=1:reset=1,
                          ametadata=mode=print:key=lavfi.astats.Overall.RMS_level"
     → 解析 stderr 拿到 20 块 RMS_level（dB）
  3. 按切点在中段（1s/0.1s = 10 块）拆分为 pre / post，分别算 dB 均值
  4. |Δ| ≥ 8 dB 视为断崖（AUDIO_CLIFF_DB_THRESHOLD = 8.0）
  处理完即 unlink 中间 wav，不污染 output/

pass 判定规则：
  visual_jump == false（severity ∈ {none, mild} 视作通过；moderate/severe 视为不通过）
  subtitle_occlusion == false
  text_clear == true
  audio_cliff == false

VLM 不可用 / 解析失败时：
  visual_* 标记为 unknown（None），不强行通过也不强行失败
  suggestions 显式标注；overall pass 只由 audio_cliff 决定

每切点评估结果
--------------

cut_1 @ 5.167s（shot1 → shot2）
  抽帧：before={4.667s, 4.867s, 5.067s}, after={5.267s, 5.467s, 5.667s}
  filmstrip：1536×161 PNG（6 帧 1x6 横向）+ JPEG ~70KB
  VLM 审查（MODEL = minimax-m3）：
    visual_jump = true，severity = moderate
    说明：切点前后从户外黄昏伞下场景直接跳到室内料理台蒸汽场景，环境/色温/角色姿态完全不同，
          属于较明显的硬切
    subtitle_occlusion = false（字幕条位于画面底部，未遮挡人物面部或核心动作）
    text_clear = true（中文字幕笔画清晰可读，无乱码/截断）
    score = 62，opinion：叙事需要的有意切换，字幕未遮挡主体，整体可接受但略显生硬
  Audio Cliff：cut_1 平滑
    pre-cut mean RMS = -41.98 dB（5 块：4.5s/4.6s/4.7s/4.8s/4.9s）
    post-cut mean RMS = -42.48 dB（5 块：5.5s/5.6s/5.7s/5.8s/5.9s）
    Δ = -0.49 dB（远低于 8 dB 阈值）
    cliff = false，verdict：音频平滑：pre=-42.0 dB, post=-42.5 dB, Δ=-0.5 dB
  结论：
    visual_jump（moderate）= ❌ FAIL
    subtitle_occlusion = ✅ PASS
    text_clear = ✅ PASS
    audio_cliff = ✅ PASS
    → overall_pass = ❌ FAIL（视觉跳跃 moderate 视为不通过）

cut_2 @ 10.333s（shot2 → shot3）
  抽帧：before={9.833s, 10.033s, 10.233s}, after={10.433s, 10.633s, 10.833s}
  filmstrip：1536×161 PNG + JPEG ~74KB
  VLM 审查：VLM 返回 reasoning 但缺 JSON → parse_json 返回
            {"parse_error": true, "raw": "<think>...</think>"}
            → 走 setdefault 容错路径：visual_jump=false, severity=unknown,
              score=0, opinion=""
            （不阻塞 pipeline；视觉相关检查标 ❓）
  Audio Cliff：cut_2 断崖
    抽段 [9.333s, 11.333s]（2s wav，32kHz mono）
    astats 20 个 100ms 块全部解析成功
    pre-cut mean RMS = -42.94 dB（ambient-only）
    post-cut mean RMS = -25.79 dB（ambient + narration）
    Δ = +17.16 dB（远超 8 dB 阈值）
    cliff = true，verdict：音频断崖：跃升 17.2 dB (pre=-42.9 dB, post=-25.8 dB)
  结论：
    visual_jump（unknown）= ❓ 无法判定
    subtitle_occlusion（unknown）= ❓ 无法判定
    text_clear（unknown）= ❓ 无法判定
    audio_cliff = ❌ FAIL（Δ=+17.16 dB 断崖）
    → overall_pass = ❌ FAIL

cut_2 音频断崖根因（对照 Phase D p5_v6_audio.py）：
  p5_v6_audio.py 混音链路中：
      narration.adelay = 10330ms（shot3 起点）
      piano.adelay     = 11500ms
      ambient          = 全程 + 2s fade-in / 2.5s fade-out
  cut_2 位置 = 10.333s ≈ narration.adelay 起点（10.330s）
  因此 pre-cut RMS 反映「ambient-only ≈ -42.9 dB」（平稳底噪）
       post-cut RMS 反映「ambient + narration ≈ -25.8 dB」
  Δ = +17 dB 是因为 edge-tts 配音「雨还在下，他走得不快。」 直接硬切进入，
  没有 fade-in 衔接，造成可感知的"音频断崖"。
  这是 Phase D 既定行为（narration 按 shot3 起 adelay 硬切，未做渐入）；
  改进建议：给 narration 加 afade=in:st=10.33:d=0.5，让底噪→配音平滑过渡。

已知限制 / 后续可改
-------------------
- cut_2 VLM 返回 reasoning 但缺 JSON：parse_json() 返回
    {"parse_error": true, "raw": "<think>...</think>"}
  脚本用 setdefault 容错把视觉三项标为 unknown（None），
  不强行判定为通过/失败，整体 pass 由 audio_cliff 决定；JSON 里
  保留了 raw 原貌（可手动核对 VLM 真实答案）。
  重跑建议：换 prompt（如明确说明 "Return ONLY a JSON object"）或
  调整聊天模型温度（默认 _r2v.chat 走 minimax-m3，温度未在脚本里硬编码）。

- audio 断崖阈值 8 dB 是经验值；如需更严格可改 AUDIO_CLIFF_DB_THRESHOLD。
  Phase D 的 narration.adelay=10330ms 硬切产生的 17 dB 跃升在阈值上
  绰绰有余，不会被误判为"audio 平滑"。

- 抽帧时刻 BEFORE/AFTER_OFFSETS 默认 ±0.5s 等距 3 帧（无重叠、覆盖切点前后
  各 500ms）。如需更密集的采样可调 --n-frames N（脚本会按比例重算偏移）。

- shot 边界用 storyboard.duration 累加计算；若上游 storyboard 增加
  start_time 字段，脚本自动改用显式值（parse_shot_boundaries 优先级 1 → 2 → 3 → 4）。

- filmstrip 长边限制 1536px（来自 filmstrip.py 的 MAX_LONG_EDGE）。
  6 帧 1x6 横向会按比例缩到 1536×161（~70KB JPEG / ~330KB PNG）。

- audio 检测只覆盖音频"响度断崖"，不识别音频内容异常（卡顿、pop、底噪突变）。
  如需更细粒度可在 astats 之外加 aphaser / afreqshift 等专项 filter。

- output\cut_point_review\_audio_tmp\ 在 evaluate_cut_point 的 finally 块
  unlink 中间 wav，正常退出后目录为空。异常退出可能残留 wav，下次运行会
  被覆盖，无累积污染。

- exit code：overall_pass → 0；FAIL → 1。可被 shell 直接当 gate 用。

- suggestions 是基于规则的模板（视觉跳跃 → crossfade；字幕遮挡 → 调整位置；
  字幕不清晰 → 加大字号；音频断崖 → 淡入淡出），未做 VLM-driven 建议生成。

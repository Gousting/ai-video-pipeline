OverlayProvider 设计
--------------------
定义在 scripts\overlay.py，统一接口：
  - id: str             provider 标识
  - render(composition, data, out) -> Path
    composition: Mapping[str, object]  至少 width / height（HyperFrames 还要 duration / fps）
    data:        Mapping[str, object]  模板占位符 + provider 参数（如 quality / timeout_s）
    out:         Path                   输出文件（PNG / MP4）
Protocol 用 typing.Protocol；registry 函数 get_provider(engine) 做 (pil|hyperframes|remotion) 路由。

三种 provider：
  PilProvider           Pillow 画半透明黑底字幕条 → PNG，含字体自动回退（中英字体都没装也能跑）
                       DEFAULT：1920x1080、底部 18% 黑底、48px 字号、白色文字居中。
                       可在 data 里覆盖 font_size / bar_ratio / text_color / bg_color / font_path 等。
  HyperFramesProvider   subprocess 调 `npx --yes hyperframes render`，
                       流程：临时目录 → init blank → 覆写 index.html（占位符替换）→ render。
                       占位符：
                         {{key}}             ← 文字内容（标题、副标题、字幕正文等）
                         data-*="__KEY__"   ← 同时也认
                         __WIDTH__ / __HEIGHT__ / __DURATION__  ← 画布与时长，由 render 自动注入
                       兜底 init：在 npx 拉不到包时手工写最小 index.html + hyperframes.json + package.json。
  RemotionProvider      NotImplementedError 占位，留给将来的数据驱动视频接入。


storyboard overlay 字段 schema
------------------------------
顶层 overlays[]（片头 / 片尾 / 整片转场）：
  { "id": "title-card", "engine": "hyperframes", "template": "title-card",
    "data": {"title": "...", "subtitle": "...", "tagline": "..."},
    "duration": 4.0 }

每个 shot.overlay（per-shot，字幕条 / 人名条）：
  { "engine": "pil", "template": "subtitle-bar",
    "data": {"text": "这座城市睡着以后..."} }

CLI：
  python scripts\render_overlays.py examples\sample_storyboard.json
  python scripts\render_overlays.py examples\sample_storyboard.json --demo
  python scripts\render_overlays.py examples\sample_storyboard.json --out D:\foo\bar

demo storyboard 自动叠三层 overlay：
  1) title-card（HyperFrames 渲染 4s MP4）
  2) 每个有 narration 的 shot → subtitle-bar（PIL 渲染 PNG）
  3) end-card（HyperFrames 渲染 4s MP4）

兜底策略：HyperFrames 渲染失败时自动用 PIL provider 再渲一次 PNG，并在 manifest 里
记 status="fallback_ok"、note 说明原因。默认 fallback-engine=pil。

HyperFrames 在本机是否可用
--------------------------
结论：可用。

- npx 检测：C:\nvm4w\nodejs\npx.cmd --version = 11.11.0（Windows 上 npx 是
  shim，无 .exe 后缀；provider 已自动 _find_npx() 改用 npx.cmd）
- hyperframes 包：v0.7.109（npm registry, Apache-2.0, HeyGen-Com 维护）
- Chrome 浏览器：v152.0.7928.2（hyperframes browser ensure 自动从 Google
  Chrome for Testing CDN 下载到 %USERPROFILE%\.cache\hyperframes\chrome）

注意事项：
- 首次 render 之前需先 `npx --yes hyperframes browser ensure`，本机已执行。
- Windows 上 `npx --yes hyperframes` 子进程 stderr 是 GBK/CP936 字节流；provider
  decode 时用 errors='replace'，避免 UnicodeDecodeError 吃掉错误信息。
- 单次 render 超时默认 600s（draft quality），实测 1s 854x480 字幕约 17s，
  4s 1920x1080 title-card 约 35s（含冷启动 Chrome）。CI / orchestration 可
  在 data 里覆盖 timeout_s。
- 不可用兜底：render_overlays 默认 fallback-engine=pil；当 is_available=False
  或 render 抛错时自动降级为 PIL PNG，并在 manifest 同步记 status/note。

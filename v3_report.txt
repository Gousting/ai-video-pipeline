## 2. 段间引导工艺（v3.1 核心增量）

### 2.1 工艺说明

参考 MiniMax 官方"海螺/H3 导演台"对 60s+ 视频的处理方式：H3 单段上限 15s，60s+ 必分段。官方解决分段衔接的核心是**段间引导**——提取前段末尾 N 帧作为下一段的生成引导条件。本地复刻路径：

1. **shot01 复用**（v3 已生成、自查通过，作为 v3.1 首段）
2. **shot02** first_frame = shot01 末帧（`v31_extract_tail.py` 抽取）→ I2V 锚定
3. **shot03** first_frame = shot02 末帧 → … 依次类推至 shot08
4. **段间过渡** xfade 0.4s + acrossfade 0.4s（与 xfade 对齐的音频淡入淡出）
5. **公共角色参数** `char_blocks.json`（CHAR_SENIOR/CHAR_JUNIOR/ANTI_BLOCK）每段保持字面一致
6. **统一 BGM**：4 段式起承转合 C 大调 120 BPM 全片循环（v3 仅末 4s 钢琴收束）
7. **段原生音轨废弃** + edge-tts 配音按 7.75s 间隔 adelay 混音

## 6. 拼接/包装/音频修复记录

v3.1 实施过程中遇到并修复 3 个问题（均在 v3_final.py 既有代码中潜伏）：

| # | 问题 | 原因 | 修复 |
|---|---|---|---|
| 1 | final_v3.mp4 截断到 15.625s | `concat_via_xfade` 用常数 offset（每段都用 `i*8 - xfade_sec`），导致后续链全部从 0 起算、覆盖前一段，最终输出被压回 8s | `v31_concat.py` 重写 offset 为**累积式** `i × (seg_dur - xfade_sec)`；并加 `-fflags +genpts` 修正 container duration |
| 2 | video_with_overlay.mp4 被截断 | v3_final.burn_overlays 用 `-shortest`，ffmpeg 在 PNG 无音频时按视频流最短截断 | `v31_burn_overlays.py` 改用 `-t <duration>` 显式锁定时长 |
| 3 | VLM 401 AuthError | `.env` 文件头部有 UTF-8 BOM，`vlm_config.py._parse_env_file` 未去除 BOM 导致 `VLM_API_KEY` 被识别为 `"\ufeffVLM_API_KEY"` | `vlm_config.py` 加 `text = text.lstrip("\ufeff")`；同时清理 `.env` BOM |

### 6.1 拼接参数选择验证

- **xfade=0.4s**（最终采用）：综合分 62.2 ✓  
- **xfade=0.6s**（测试）：综合分 42.2 ❌（混合帧糊化拉低画面质量）
